# SOP: Accept a signed client into delivery

**Purpose:** Start client delivery with a confirmed scope, responsible owner and agreed first milestone.
**Process owner:** Delivery operations lead
**Last reviewed:** Example only — replace after your team's first review
**Use this when:** Sales marks the agreement signed and requests handoff.
**Required inputs:** Signed agreement URL, scope summary, client contact, service start date, key deliverables, open commercial promises.

## Steps
1. **Validate the handoff.** Open the signed agreement and compare it with the scope summary; confirm the client contact and start date are present.
2. **Create one delivery record.** Use the agreement's ID to check whether the client record already exists. Add or update the shared tracker; do not create a duplicate.
3. **Assign an accountable owner.** Record the person responsible for client setup and the target date for the first milestone.
4. **Confirm readiness.** The owner checks access requirements, key risks and outstanding dependencies; escalates anything that could prevent the agreed start.
5. **Acknowledge the handoff.** Post the delivery record URL and first milestone back to the handoff thread so Sales and Delivery are looking at the same status.

## Definition of done
- [ ] The signed agreement and scope link are accessible to authorized teammates.
- [ ] One delivery record exists, with an accountable owner and start date.
- [ ] The client’s first milestone and open dependencies are visible.
- [ ] Sales receives a link to the accepted handoff.

## Exceptions and escalation
| If this happens | Stop / continue? | Who decides? | Where to record it? |
| --- | --- | --- | --- |
| Scope differs from signed contract | Stop | Sales owner + delivery lead | Handoff record |
| Start date conflicts with staffing | Stop | Delivery lead | Capacity review |
| Missing optional reference material | Continue if not blocking | Delivery owner | Open-dependency field |
| Duplicate client record | Update existing record | Operations owner | Audit note |

**Fictional example:** Adapt to your actual contract and data-protection procedures. It is not legal guidance.
